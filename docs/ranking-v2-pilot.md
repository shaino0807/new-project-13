# 排行榜第二版與 250 檔效能試跑

更新日期：2026-08-26

## 使用者要的真正排行榜

正式排行榜的母體不是固定 64 檔。流程固定為：

1. 先讀取完整上市、上櫃公司目錄，排除興櫃。
2. 為母體中的每家公司建立一次共同特徵資料。
3. 低估、高估、成交活躍、現金流、成長及小資六種排行榜，各自使用自己的主分數獨立排序。
4. 每種排行榜各取自己的前 64 名。

排序相同分數時依序比較：資料覆蓋率、報價日期、股票代碼。任何正式名次都必須同時具備主分數、報價日期、至少 60% 資料覆蓋率，而且沒有過期資料。

## 已修正的舊問題

- 舊發布流程雖然分批掃描市場，最後卻只拿「各榜暫存前 40 名的聯集」發布，因此無法從完整母體誠實選出每榜前 64 名。
- 新流程在發布前重新讀取所有已保存的公司特徵，再讓六種排行榜各自排序及取前 64 名。
- 正式門檻由舊 55% 統一為 60%，並加入無過期資料條件。
- 排行快照保留產業、漲跌、資料覆蓋率、過期資料、信賴狀態、報價日期及更新時間。
- 首頁改讀已完成快照，不再因訪客開啟首頁而執行 `/api/workbench` 的 64 檔重算與回測。
- 未指定自訂股票清單的舊 `/api/screener` 路徑也改為讀取已完成快照；只有明確送入自訂清單時才會做同步研究批次。

## 250 檔試跑怎麼選

250 檔只用來驗證資料成本及效能，不是正式全市場排行榜。

試跑先一次讀取 TWSE 與 TPEx 的官方全市場日行情，以最新成交金額在各市場內分成高、中、低三個流動性層級；若當日行情找不到該公司，會誠實標成「無可用流動性資料」。接著依「市場別＋官方產業＋流動性層級」分桶，每桶至少選一個固定代表，再以系統化間距從剩餘公司補足 250 檔。輸入順序即使顛倒，也會選到相同名單。

流動性分層只需兩次官方批次請求，不必為了選樣本先逐檔抓取 1,985 次報價。成交金額缺漏時，才以成交量乘收盤價作備援；兩者皆缺時不補造資料。

2026-08-26 唯讀檢查公開公司目錄：

- 上市：1,133 家
- 上櫃：852 家
- 上市＋上櫃：1,985 家
- 興櫃：535 家，這一階段排除
- 250 檔樣本：上市 139、上櫃 111，涵蓋 65 個「市場別＋產業」分桶
- 樣本流動性層級：高 62、中 70、低 74、無可用資料 44

## 本機試跑結果

執行：

```powershell
node scripts/ranking-v2-pilot.mjs --live-universe
```

已通過：

- 250 個代碼皆不重複，而且全部來自目前 1,985 家上市、上櫃公司目錄。
- 顛倒公司目錄輸入順序後仍得到同一份 250 檔樣本。
- 六種排行榜各自從 250 檔取 64 檔，合成資料下六種成分集合皆不同。
- 55% 覆蓋率或含過期來源的合成資料不會進入正式名次。
- 1,000 次「250 檔資格過濾＋六榜排序」本機 CPU 約 0.20 秒，平均每次約 0.20 毫秒；因此真正瓶頸是外部資料讀取，不是排序運算。

這個本機數字不能當成 250 檔真實資料抓取時間。它只證明母體選樣、門檻與排序邏輯能重現。

## 報價路由、官方每日快取與結果分類

2026-08-26 的第二輪本機修正保留原本 250 檔抽樣算法，不靠更換樣本提高成功率：

- 公司目錄標示 `twse` 時，Yahoo 只請求 `.TW`；標示 `tpex` 時只請求 `.TWO`。只有市場未知的單股相容路徑才保留受控的雙後綴探測。
- TWSE `STOCK_DAY_ALL` 與 TPEx `tpex_mainboard_quotes` 由共用載入器按台北日曆日快取，並共享同市場的進行中請求。250 檔 pilot 建立樣本時會把已取得的官方報價列保存到公司 profile，後續分批評分不必重抓同一整批行情，也不再為已有官方日行情的樣本逐檔請求 MIS 即時報價。
- 官方行情日期只接受來源欄位；不再以伺服器當日日期冒充交易日。
- `suspended_or_halted` 只接受 TWSE `TWTAWU`、TPEx `tpex_spendi_today` 或行情列中的官方明確停止／暫停交易證據；停／復牌清單也按台北日曆日快取，並以停牌日、復牌日及該批官方行情的交易日判斷，不能因歷史紀錄仍在清單內就誤標為目前停牌。官方行情端點正常但個股沒有可用報價列為 `no_quote_for_latest_session`；逾時、HTTP／傳輸失敗或無效 payload 列為 `provider_failure`；已有分數但未通過排名證據門檻列為 `not_rankable`；證據不足則保留 `unresolved`。
- 已有舊 Yahoo 歷史但官方最新交易日沒有報價的股票，不會只因歷史資料存在就被視為可排名。
- 每次 deterministic pilot 都輸出樣本指紋，方便比較修正前後是否使用相同抽樣算法與成分。

這一節只記錄本機程式與契約修正。AppDeploy 部署及新的遠端 250 檔實測仍是分開的外部寫入閘門；在取得各自確認前不執行。

- 有分數、報價日期、60% 覆蓋率、無過期資料及最終可列入排名的完整率
- 依目前速度推估 1,985 檔所需時間

試跑完成後只產生明確標示為 `pilot-only` 的結果，不會啟用或取代公開正式排行榜，也不會更新公開產業快照。

外部請求計數已放在共用請求層：只有真正送往供應者的 HTTP 請求才計入總數，快取與同批共用中的請求另外計數，不會把邏輯上的重複讀取誤算為新增流量。1,985 檔推估會保留固定的目錄與全市場行情成本，只放大逐檔評分部分。

## Phase C.5：1,985 檔精度優先的本機改造

這一階段以完整上市／上櫃普通股母體為目標，把耗時從逐檔重抓改成市場日批次與增量更新；1,985 檔是固定合成測試基準，不是當日公司數。2026-08-26 完成本機程式、契約與合成驗證；後續部署與受控 pilot 的狀態見下方更新，尚未產生或啟用正式全市場快照。

### 降低耗時的方法

- 以 TWSE、TPEx 市場別直接選擇官方端點與 Yahoo 後綴，不再先試錯市場。
- 官方歷史行情改用「市場＋交易日」整批取得。每個市場保存最近 120 個有效交易日，再轉置成每 20 檔一批的個股歷史；之後每日正常情況只需補新交易日，不必為 1,985 檔各下載一年歷史。
- 評分批次固定 20 檔、同時最多 4 檔；1,985 檔共 100 批。這是受控並行，不代表同時對來源送出 1,985 個請求。
- 只重試暫時性的 `provider_failure`。停止交易、官方當日無報價、證據不足及真正不可排名都有終局分類，不浪費第二輪請求。
- 已驗證的 FinMind 財報、現金流、資產負債表及月營收資料可寫入每日持久快取；憑證只由後端 `FINMIND_TOKEN` 讀取，不進程式碼、文件或聊天內容。
- TWSE 與 TPEx 月營收各走自己的官方整批端點，不再把上櫃公司誤送到上市資料表。

### 不可放寬的精度門檻

- 六種排行榜各自有必填欄位契約。共同的 60% 覆蓋率只是一層基本門檻，不能代替現金流、成長、估值或技術模式真正需要的欄位。
- 低估／高估要求至少兩項官方估值欄位、EPS、月營收 YoY、營業現金流、負債比與 20／60MA；其他模式也各有獨立必填欄位。
- 20MA 技術強勢不是「站上均線」的簡化代名詞。必須同時通過：站上且 20MA 上揚、突破下降壓力線、W 底突破頸線、最新量至少為先前 20 個交易日均量的 1.5 倍；任一條失敗就不得進榜。
- 每榜保存第 50 至 90 名供邊界稽核，明確比較第 64 與第 65 名，並以主分數、覆蓋率、報價日期、股票代碼完成決定性排序。
- 除了至少 95% 建檔成功率，正式啟用還要求 `provider_failure` 與 `unresolved` 都為零。已確認停止交易或官方當日無報價可以是完整處置，但不會取得假名次。
- 排名工作若找不到至少 60 個已驗證交易日，會直接失敗；合成歷史只保留給非正式的單股相容流程，不能進正式排行榜。

### 本機 1,985 檔模擬結果

執行 `node scripts/ranking-v2-pilot.mjs` 已通過：完整 1,985 檔、20 檔批次、100 批、並行 4；六榜各 64 名；輸入顛倒後排序一致；六榜的第 50 至 90 名邊界資料完整；缺少現金流期末現金或成長 EPS YoY 的列會被拒絕；20MA 四條件逐一失敗時都會被拒絕；只有來源故障會進入重試。

這是本機合成資料與原始碼契約檢查，不能被解讀成正式資料已抓完。官方 TWSE／TPEx 市場日行情端點已做唯讀格式驗證，但 AppDeploy 上的 120 日保存量、工作記憶體與實際完整掃描時間仍需下一個獨立遠端 pilot 才能量測。MOPS 現金流頁面的自動請求在本次檢查中回傳安全阻擋頁，不能宣稱是可用的官方現金流批次來源；若現金流與成長榜要維持上述精度，仍需在部署環境安全設定 `FINMIND_TOKEN`，或另取得具授權且可驗證的結構化來源。
